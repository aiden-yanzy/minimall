# 部署与运维

## 零、云服务器一键部署演示站（最快）

在一台装了 Docker 的 Linux 服务器（2G 内存起）上执行：

```bash
git clone https://github.com/aiden-yanzy/minimall.git && cd minimall
bash scripts/deploy-demo.sh          # 默认前端 18080、后端 18082，装到 ~/minimall
```

> 国内服务器 clone GitHub 慢的话，可以先配好代理或改用镜像源；也可以把仓库下载成 zip 传上去再解包。
> `curl raw.githubusercontent.com/...` 的形式在国内常常连不通，**推荐用上面的 clone 方式**。

脚本会依次：检查 Docker / 内存 / 磁盘 → 拉代码 → 生成 `.env`（JWT 密钥自动随机化）→ `docker compose up -d` → 轮询等后端就绪 → 校验三端 200 → 放行本机防火墙 → 打印访问地址。

常用参数：

| 参数 | 作用 |
|---|---|
| `--port 8080` | 换前端端口（后端自动用 +2）|
| `--dir /opt/minimall` | 换安装目录 |
| `--reset` | 清空数据卷重建（**会丢数据**）|

**国内云服务器绑域名走 80/443 需要备案**，但用「公网 IP + 非标端口」不需要备案，脚本默认就是这个方式。打不开先去云厂商控制台的安全组放行该端口（入方向 TCP）。

> 演示站注意事项：数据库里是演示数据，公网暴露后随时可能被改；不要放真实用户信息。想限制访问可以在 nginx 前加一层 basic auth 或 IP 白名单。

## 一、一键部署（单机 Docker Compose）

```bash
git clone <your-repo-url> minimall && cd minimall
cp .env.example .env        # 可选，不改也能跑
docker compose up -d
docker compose ps           # 四个容器都应 Up（mysql / redis 带 healthcheck）
```

首次启动 `minimall-mysql` 会自动执行 `server/src/main/resources/sql/minimall-init.sql` 建表并写入种子数据（商品、分类、优惠券、秒杀、会员等级、演示账号等）。

### 端口

| 服务 | 默认端口 | 说明 |
|---|---|---|
| nginx（前端入口） | **18080** | `/` H5 · `/pc/` PC · `/admin-web/` 后台 · `/file/` 上传文件 |
| server（后端） | **18082** | `/shop/**` `/admin/**` `/pay/**` 以及 `/swagger-ui.html` |
| mysql | 不对外 | 需要连库调试时自己开 `ports` |
| redis | 不对外 | 同上 |

端口都在 `.env` 里改（`WEB_PORT` / `SERVER_PORT`），改完 `docker compose up -d` 重建即可。

> 用高位端口是为了避开 8080 这类常被其他服务占用的端口；同时绑 `0.0.0.0` 方便局域网/手机调试。

## 二、后端改动怎么发布

容器内跑 Maven 拉依赖经常失败（网络问题），所以采用「本机打包 + 薄运行镜像」：

```bash
cd server
mvn -q -DskipTests package          # 产出 target/minimall-server.jar（约 46MB）
cd ..
docker build -f server/Dockerfile.runtime -t minimall-server:latest ./server
docker compose up -d --no-build server      # 约 40 秒生效
```

`Dockerfile.runtime` 只有一句 COPY + 一个 JRE 基础镜像，构建几秒完成。

## 三、前端改动怎么发布

```bash
# 后台
cd admin && npm run build && rsync -a --delete dist/ ../deploy/www/admin/

# PC 商城
cd pc && npm run build && rsync -a --delete dist/ ../deploy/www/pc/

# C 端 H5 —— 注意 deploy/www 根目录同时放着 pc/ admin/ landing.html，
# 直接 --delete 同步会把它们删掉，必须排除
cd uniapp && npm run build:h5 && cd ..
rsync -a --delete --exclude 'pc' --exclude 'admin' --exclude 'landing.html' \
      uniapp/dist/build/h5/ deploy/www/
```

nginx 直接从 `deploy/www` 提供静态文件，同步完刷新页面即可，无需重启容器。

> ⚠️ `deploy/www` 是 nginx 的静态根，`rsync --delete` 的目标一定要精确到子目录，否则一同步就把另外两端的产物删了（这个坑踩过）。

## 四、健康检查

```bash
# 容器状态
docker compose ps

# 三端是否可访问（都应返回 200）
for u in / /pc/ /admin-web/; do
  curl -s -o /dev/null -w "%{http_code} $u\n" "http://localhost:18080$u"
done

# 接口探活
curl -s "http://localhost:18082/shop/decorate/home" | head -c 200

# 全链路冒烟（25 项断言）
python3 scripts/smoke.py --skip-concurrency
```

## 五、日志

```bash
docker compose logs -f server                 # 后端实时日志
docker compose logs --since 10m server | grep -E "ERROR|Exception"
docker compose logs --tail 100 nginx          # 访问日志（404/502 排查）
```

后端已开启 SQL 日志（`mybatis-plus.configuration.log-impl=Slf4jImpl`），调试时可看完整执行语句。

## 六、数据备份与恢复

```bash
# 备份（建议放外置盘或对象存储，别只留本机）
docker exec minimall-mysql mysqldump -uminimall -pminimall123 \
  --single-transaction --routines minimall > backup-$(date +%F).sql

# 恢复
docker exec -i minimall-mysql mysql -uminimall -pminimall123 minimall < backup-2026-01-01.sql
```

上传的图片在 docker volume（`upload-data`）里，一并备份该卷。

## 七、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 后台页面白屏，HTML 是 200 | Vite 的 `base` 必须写在 **config 顶层**（写在 `build: {}` 里会被静默忽略），产物资源路径会指到别处 |
| 登录后 `/admin/auth/me` 报 401 | admin 与 user 是两套 Sa-Token 体系；取当前管理员权限必须走 `stpAdmin`，用默认 `StpUtil` 会直接 401 |
| 秒杀商品一直「已抢完」但库存有货 | Redis 库存 key 漂移；当前已实现「key 缺失按 DB 回源 + 扣成负数校正重试」，如仍异常可 `docker exec minimall-redis redis-cli del seckill:stock:{id}` |
| 下单体感「有货却提示库存不足」 | SPU 的 `goods.stock` 与 SKU 合计漂移。以 SKU 为准，可执行 `update goods g set stock=(select coalesce(sum(stock),0) from goods_item gi where gi.goods_id=g.id and gi.delete_flag=0)` 校正 |
| 支付成功但订单还是待支付状态 | 当前支付是模拟直通 `/shop/pay/mock`；接真实支付后由回调 `/pay/notify/wechat|alipay` 驱动 |
| 端口被占用 | 改 `.env` 的 `WEB_PORT` / `SERVER_PORT` 后 `docker compose up -d` |
| 完全重来 | `docker compose down -v`（**会删除数据卷**，含上传图片与数据库）|

## 八、公网部署清单

1. **改掉所有默认口令**：`.env` 里的 MySQL 口令、`SA_JWT_SECRET`（换成 32 位以上随机串）
2. **HTTPS**：nginx 挂证书，或在前面加一层 Caddy / Nginx Proxy Manager
3. **只暴露 443/80**：mysql / redis / 后端端口都不要对外
4. **对象存储**：把 `minimall.upload-dir` 换成 OSS/COS，避免图片随容器丢失
5. **定时备份**：数据库 + 上传目录，保留最近 N 份
6. **日志与监控**：至少接一个错误日志告警（后端 `ERROR` 关键字 + 容器重启事件）
