# 演示脚本（5 分钟走完）

给演示 / 面试 / 交付用的一条龙路线。每一步都标了**看点**，照着点不会冷场。

前置：`docker compose up -d` 已启动，三端可访问（见 [部署与运维](03-部署运维.md)）。

**演示账号**

| 端 | 账号 |
|---|---|
| 后台（超管） | `admin / admin123` |
| 后台（运营，看权限差异） | `operator / admin123` |
| C 端（种子会员） | `13800138000 / 123456`（也可自行注册）|

## 0. 开场（30 秒）

| 打开 | 地址 |
|---|---|
| H5 商城 | http://localhost:18080/ |
| PC 商城 | http://localhost:18080/pc/ |
| 后台 | http://localhost:18080/admin-web/ |

一句话交代技术栈与规模：**Spring Boot 3 + Vue3 四端（后台 / PC / H5 / 小程序），201 个接口、65 张表；营销域覆盖券·满减·秒杀·拼团·砍价·预售·积分·签到·抽奖；交易链路含售后闭环与分销结算。**

## 1. 后台配置（90 秒）

用 `admin / admin123` 登录。

### 1.1 商品与多规格 SKU
**商品管理 → 编辑任一商品**

> 看点：规格组（颜色 × 尺码）自动生成 SKU 矩阵，可批量填价格/库存；保存后立即反映到 C 端。

### 1.2 首页可视化装修
**内容装修 → 首页装修**

> 看点：左侧改轮播/宫格，右侧**手机预览实时同步**；服务端会校验（轮播必须 1~8 张且每张有图，宫格名称不能为空），脏数据进不去。

### 1.3 权限差异（强烈建议演示）
**退出 → 用 `operator / admin123` 登录**

| | 超管 admin | 运营 operator |
|---|---|---|
| 侧栏菜单 | 24 项 | 少了用户/会员等级/品牌单位/财务/角色/设置/运费/提现/内容装修 |
| 商品页「删除」按钮 | 有 | **没有**（无 `goods:delete`）|
| 直接调删除接口 | 通过权限 | **403 没有权限** |

> 看点：权限不是「前端藏按钮」的假权限，后端 `@SaCheckPermission` 兜底。演示时可以直接用浏览器 F12 或 curl 打接口证明。

## 2. C 端下单主链路（120 秒）

用 H5（手机尺寸）操作更直观。

1. **领券**：首页 → 领券中心 → 领取「满 300 减 50」
2. **搜索**：点搜索框 → 有搜索历史与热门搜索 → 搜「耳机」
3. **商品详情**：选规格 → 加购
4. **下单**：购物车 → 结算 → 选地址 → **看价格分层**：商品总额 → 会员折扣 → 满减 → 优惠券 → 实付
5. **支付**：点「立即支付」（模拟支付直通）
6. **会员成长值**：支付成功后进「会员中心」，累计消费与等级进度立即变化

> 看点：价格计算是分层的、可见的，不是一口价。

---

## 3. 后台处理订单（60 秒）

回后台（`admin`）：

1. **订单管理**：找到刚下的单 → 发货（填快递单号）
2. **物流轨迹**：订单行点「轨迹」→ 可见真实落库的节点，还能「模拟推进」走下一步
3. **销售统计**：工作台/统计页看今日销售额、商品排行

> 看点：轨迹是落库的（不是前端拼的假数据），有需要时后台可以补录节点。

---

## 4. 售后闭环（90 秒，最能体现完成度）

1. C 端 → 我的订单 → 已完成订单 → 商品行点「售后」
2. 选「仅退款」→ 退款金额（可一键全额）→ 选快捷原因 → 提交
3. 后台 → **售后管理** → 该单「同意退款」
4. 回 C 端 → 我的钱包：**余额增加，流水显示「售后退款 ASxxx」**；商品库存同步恢复

> 看点：退款不是只改状态 —— 钱真的进了余额并留下流水，库存也回补了（秒杀单还会回补秒杀库存）。

---

## 5. 分销（60 秒）

1. C 端 → 我的 → **分销中心** → 拿到邀请码与推广链接
2. 用无痕窗口打开推广链接 → 注册新用户（**自动绑定邀请人**）
3. 新用户下单 → 后台发货 → 新用户确认收货
4. 回推荐人的分销中心：**累计佣金 / 本月佣金 / 团队人数 / 佣金明细**全部更新，等级进度条前进

> 看点：确认收货那一刻才结算佣金（避免刷单），费率按**卖家本人累计佣金**匹配到的等级（普通 10% → 高级 15%）。

---

## 6. 收尾：一条命令验全链路（30 秒）

```bash
python3 scripts/smoke.py
```

25 项断言：注册 → 领券 → 下单 → 支付 → 发货 → 轨迹 → 收货 → 评价 → 成长值 → 售后 → 退款到余额 → **并发 20 打 5 件库存（恰好 5 单成功、无负库存）**。

> 看点：主流程不是「手点过」，而是可重复验证的；并发那项能直接证明防超卖是真的。

## 备用：常见追问怎么答

| 追问 | 回答要点 |
|---|---|
| 怎么防超卖？ | `UPDATE ... SET stock = stock - n WHERE id = ? AND stock >= n`，扣不动即抛「库存不足」回滚；下单前的校验只做快速失败 |
| 订单一直不支付怎么办？ | 定时任务每分钟扫未支付单，普通 30 分钟、秒杀 5 分钟自动关单（CAS 抢状态防误杀），同时恢复库存、回补秒杀库存、退回优惠券 |
| 秒杀怎么抗？ | Redis 预扣库存 + DB 双写；key 缺失按 DB 回源，扣成负数校正重试 |
| 权限怎么做的？ | 后端下发权限码 → 前端菜单/按钮按码渲染 → 后端 `@SaCheckPermission` 兜底；admin 与 user 是两套 Sa-Token 体系 |
| 支付是真的吗？ | 目前是模拟直通，回调接口按微信/支付宝签名结构预留；接真实支付需要商户号与证书 |
| 有哪些没做？ | 真实支付与验签、小程序 wx.login、短信、对象存储、单元测试与 CI（README 已列清） |
