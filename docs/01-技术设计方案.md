# Minimall 单商户商城 —— 技术设计方案（v0.1 待确认）

> 需求基准：likeshop 单商户 SaaS 商城（PHP）的业务设计 / 功能 / 页面风格（仅借鉴思路，不复制代码）
> 技术栈：Java · Spring Boot 3.x · MyBatis-Plus · MySQL 8 · Redis · JWT · Vue3
> 交付物：本文案 = 功能清单 → 表设计 → 接口规范 → 技术选型 → 目录结构 → 迭代计划

---

## 0. 一句话定义

一套**单商户（一个店铺）、双端（C 端用户 + 商家后台）**的自营商城系统。
C 端用 **Vue3 + uni-app** 一套代码编译出 **H5（手机/电脑浏览器）+ 微信小程序**；
后台用 **Vue3 + Element Plus**（或 Vben Admin 模板）纯 Web 管理端。
后端为 **Spring Boot 3 单体应用**，Docker Compose 一键起（MySQL + Redis + 后端 + 前端）。

**明确砍掉**（单商户不需要）：SaaS 平台端、多商户/入驻、商家独立 App、客服坐席系统（客服功能保留为 C 端会话，但坐席后台做简化版）。

| 层 | 选型 | 说明 |

| 语言 | Java 17 | Spring Boot 3.x 要求 |
| 框架 | Spring Boot 3.3.x | 单体 |

| 工具 | Lombok / Hutool / MapStruct | |
| 构建 | Maven + maven-wrapper | |
| 部署 | docker + docker-compose | nginx 反代前端与后端 |

> 认证建议用 **Sa-Token**（比 Spring Security 对"双端登录+权限"友好得多，国内商城常用）。如果你坚持 Spring Security 也可以，备注说明。

## 2. 整体架构

```
                        ┌──────────────────────────────────────────┐
   手机浏览器 / 微信小程序 │  C 端 (uniapp Vue3)   ── 编译 H5 + 小程序  │
                        └──────────────────────────────────────────┘
                                      │ REST (JSON) + JWT
                        ┌──────────────────────────────────────────┐
       后台浏览器        │  Admin (Vue3 + Element Plus)              │
                        └──────────────────────────────────────────┘
                                      │ REST (JSON) + JWT
        ┌─────────────────────────────▼─────────────────────────────┐
        │              Spring Boot 3 单体应用 (minimall-server)       │
        │  ┌──────────┬──────────┬─────────┬─────────┬────────────┐  │
        │  │ shop-api │ admin-api│ common  │ modules │  ...       │  │
        │  │ (C端)    │ (后台)   │ (核心)  │ (业务包) │            │  │
        │  └──────────┴──────────┴─────────┴─────────┴────────────┘  │
        │  MyBatis-Plus  ·  Redis  ·  JWT  ·  定时任务(XXL/Spring)   │
        └─────────────────────────────┬─────────────────────────────┘
                                      │
                    ┌─────────────────┴─────────────────┐
                    ▼                                   ▼
                 MySQL 8                              Redis 7
```

### 系统模块划分（按业务域）
- `minimall-server`：后端单体，内部按业务域分包（goods/order/user/marketing/finance/content/system）
- `minimall-uniapp`：C 端（Vue3 + uni-app，编译 H5 + 小程序）
- `minimall-admin`：后台（Vue3 + Element Plus）

## 4. 功能清单（完整对标 likeshop）

### 4.1 C 端（用户）
- **首页与装修**：装修页（轮播/宫格导航/广告/商品板块/直播/秒杀入口）、主题切换、开屏广告、自定义导航栏
- **商品**：分类、品牌、搜索（热门/历史）、商品详情（图/视频/规格/SKU/评价/收藏/分享海报）、商品浏览足迹
- **购物车**：增删改、选中结算、规格切换
- **交易**：下单（多地址/运费模板计算/优惠券/会员价/满减）、模拟支付、订单列表、取消/确认收货、物流查询（轨迹）、**售后/退款**
- **会员**：登录注册（手机号/微信）、会员等级、积分、个人中心、收货地址、收藏
- **营销**：优惠券领取、秒杀、拼团、砍价、预售定金、满减、积分商城兑换、幸运抽奖、每日签到、注册送
- **分销**：推广关系、佣金、提现申请
- **钱包**：余额充值、余额支付、资金流水、提现
- **互动**：文章/商城公告、门店自提（选择门店/核销）、在线客服会话（简化）
- **其他**：分享（海报/口令）

### 4.2 后台（管理员）
- **工作台/数据**：首页统计、交易转化、商品/用户分析、流量分析
- **商品**：SPU 发布（多规格 SKU/多图/视频）、分类、品牌、评价管理、单位、运费模板、供应商/供货价、采集
- **订单**：订单列表、发货/批量发货、物流查询、售后处理（退款/退货）、评价
- **营销**：优惠券、秒杀、拼团、砍价、预售、满减、免邮、会员价、积分商城、抽奖、签到、注册奖励、营销日历
- **用户**：用户列表/详情、会员等级、用户标签、邀请关系
- **财务**：账户流水、佣金明细、提现审批、积分明细
- **装修**：页面装修、PC 装修、主题、开屏、导航栏
- **设置**：基础设置、支付方式（mock/微信/支付宝）、配送（快递/自提门店）、订单设置、库存、短信、系统维护（定时任务/日志）
- **权限**：管理员、角色、菜单权限
- **应用/渠道**：分享配置、小程序配置、直播（可延后）

> 营销模块按**优先级分批**（见第 8 节迭代计划），但清单全量保留。

## 5. 数据库表设计草案（域分组）

> 以下为表清单与核心字段思路。字段名统一 `snake_case`，主键 `bigint` 自增，含 `create_time/update_time/delete_flag`。
> 完整 DDL 在确认架构后产出（`server/src/main/resources/sql/`）。

### 5.1 用户域
- `user`：id、sn、昵称、头像、手机、密码、性别、生日、余额`balance`、积分`integral`、等级`level_id`、状态
- `user_auth`：user_id、type(wechat/phone/…) 、openid、unionid —— 第三方登录
- `user_level`：等级、名称、升级门槛、折扣
- `user_label` / `user_label_index`：用户标签与关联
- `user_address`：收货地址
- `user_session`：会话/token
- `collect`：收藏（user_id、goods_item_id）
- `footprint` / `footprint_record`：浏览足迹
- `distribution`：分销关系（父/子）、`distribution_apply`（申请）、`distribution_level`、`distribution_order_goods`（订单分佣）、`distribution_config`
- `account_log`：账户变动流水（类型/余额/积分/备注）

### 5.2 商品域
- `goods_category`：商品分类（树）
- `goods_brand`：品牌
- `goods`：SPU（名称、副标题、价格区间、库存、销量、状态、缩略图、富文本详情）
- `goods_item`：SKU（goods_id、规格组合、价格、库存、图、编码、销量）
- `goods_spec` / `goods_spec_value`：规格与规格值
- `goods_image`：图片/视频
- `goods_comment` / `goods_comment_image`：评价与图
- `goods_delivery_template`：运费模板；`freight` / `freight_config`：运费计算规则
- `goods_service_guarantee`：服务保障
- `goods_unit`：单位
- `goods_supplier` / `goods_supplier_category`：供应商
- `goods_gather` / `goods_gather_goods` / `goods_gather_log`：商品采集
- `goods_visit`：访问统计；`search_record`：搜索记录
- `goods_activity`：商品与活动绑定（秒杀/拼团等）

### 5.3 交易域
- `cart`：购物车
- `order`：主订单（单号、用户、实付、支付方式、状态机、收货快照、优惠快照、物流快照）
- `order_goods`：订单商品行（SKU 快照、单价、数量、活动快照）
- `order_log`：订单状态流转日志
- `after_sale`：售后单；`after_sale_goods`；`after_sale_log`
- `refund`：退款单
- `delivery`：发货单；`delivery_batch` / `delivery_batch_info`：批量发货
- `delivery_time`：预约送达
- `recharge_order` / `recharge_template`：充值
- 各营销专属订单：`presell_order` 等并入 order 类型字段

### 5.4 营销域
- 优惠券：`coupon`（券模板）、`coupon_list`（用户领用，含状态）
- 秒杀：`seckill_activity`、`seckill_goods`、`seckill_goods_item`
- 拼团：`team_activity`、`team_goods`、`team_goods_item`、`team_found`（开团）、`team_join`（参团）
- 砍价：`bargain_activity`、`bargain_goods`、`bargain_help`、`bargain_initiate`
- 预售：`presell`、`presell_goods`、`presell_goods_item`
- 满减：`discount_goods`、`discount_goods_item`
- 免邮：`free_shipping`、`free_shipping_order`
- 会员价：并入 goods 价格体系 + `user_level`
- 积分商城：`integral_goods`、`integral_order`、`integral_order_refund`
- 抽奖：`lucky_draw`、`lucky_draw_record`
- 签到：`sign_daily`（签到配置）、`sign_log`
- 注册奖励：`register_award`

### 5.5 内容 / 门店 / 系统
- 内容：`article`、`article_category`、`notice`、`notice_setting`、`shop_notice`
- 装修：`decorate_theme`、`decorate_theme_config`、`decorate_theme_page`、`pc_decorate_theme_*`
- 门店：`selffetch_shop`、`selffetch_verifier`、`verification`（核销记录）
- 系统：`admin`、`role`、`role_auth_index`、`admin_session`、`operation_log`、`config`（键值配置）、`file`/`file_cate`、`region`（地区）、`express`（快递公司）、`pay_config`、`pay_way`、`sms_log`、`printer`/`printer_template`
- 计时/缓存辅助：`crontab`（定时任务记录）

> 单商户下 `shop` 概念简化为**系统级配置**（商户即系统本身），不建多商户表。

## 6. 接口设计规范

- **风格**：RESTful + JSON，统一前缀 `/shop`（C端）、`/admin`（后台）
- **统一响应**：`{ code, msg, data }`（code=200 成功）
- **鉴权**：请求头 `Authorization: Bearer <JWT>`；C 端用户与 admin 使用**两套独立 JWT + 独立拦截器**，防止越权
- **幂等**：下单/支付用 `order_sn` 或幂等键防重复提交
- **分页**：`page`/`size`；返回 `total`
- **金额**：统一以 `分` 存取（`int/bigint`），避免浮点误差
- **时间**：`yyyy-MM-dd HH:mm:ss`，存储 datetime
- **文档**：Swagger 自动生成 `/doc.html`
- 示例：
  - `GET /shop/goods/{id}` 商品详情
  - `POST /shop/cart` 加购
  - `POST /shop/order/create` 下单
  - `GET /admin/order/list` 后台订单列表

## 7. 关键设计决策（需你确认）

1. **认证库**：用 **Sa-Token** 还是 **Spring Security + JWT**？我推荐 Sa-Token（双端登录/角色权限更省事）。→ 请选
2. **后台 UI**：自研布局，还是用现成开源后台模板 **vben-admin / vue-pure-admin**（Vue3+ElementPlus）二次开发？我推荐用模板省大量时间。→ 请选
3. **C 端小程序**：用 **uni-app 一套代码**同时出 H5+小程序（我推荐，工作量省一半）；若你们对原生小程序有强需求再说。→ 请确认
4. **文件存储**：本地磁盘 + Docker 卷（先这样），后续接 OSS。→ 默认本地
5. **定时任务**：单体内用 Spring `@Scheduled` 起步（订单超时关单/拼团失败/活动上下架）。→ 默认
6. **模拟支付**：提供"模拟收银台"（选微信/支付宝→直接成功回调通知后端），后端支付回调接口按微信/支付宝真实签名结构预留，后续无痛替换。→ 默认

## 8. 迭代计划（建议里程碑）

| 阶段 | 范围 | 验收 |
|---|---|---|
| **P0 骨架** | 后端框架 + 统一响应/异常/JWT/日志 + Docker Compose + 前端两套脚手架 + 登录注册 | 能起环境、登录闭环 |
| **P1 商品+交易** | 分类/品牌/SPU/SKU/购物车/下单/模拟支付/订单管理/基础后台与 C 端列表详情 | 完成一次买卖闭环 |
| **P2 订单深化** | 发货/物流/确认收货/**售后/退款**/运费模板/门店自提 | 交易完整 |
| **P3 营销一根** | **优惠券 + 会员价 + 满减**（营销框架打通） | 促销可用 |
| **P4 营销二根** | 秒杀（Redis 库存）→ 积分商城 → 签到/抽奖 | |
| **P5 营销三根** | 拼团 → 砍价 → 预售（拼/砍/预状态机复杂，放最后） | |
| **P6 分销+钱包** | 分销关系/佣金/提现/充值/流水 | |
| **P7 装修+内容** | 页面装修、主题、开屏、文章/公告、客服简化版 | |
| **P8 收尾** | 数据报表、权限完善、小程序发布流程、微信/支付宝真实支付接入口、压测/文档 | |

> 顺序原则：**先跑通"钱货"主链路，再叠加促销**，营销按复杂度从低到高排。
